How I choose

I start with the problem and work back to the tool. Everything on this page earned its place by solving something specific.

Jobs have to run on time and recover on their own.
Apache Airflow
Retries, dependencies and monitoring come built in, so a failed task at 3am fixes itself or tells me exactly where it stopped.
Transformations should be reviewed like code.
dbt
SQL-first models with tests and lineage built in. Incremental models are also how I cut BigQuery query costs by around 40% on client work.
The warehouse has to scale without anyone running it.
BigQuerySnowflake
Managed warehouses when the data and the team are growing, so nobody spends their week on operations.
The data fits on a laptop.
DuckDBParquet
Then it should stay there. Fast local analytics with nothing to provision and nothing to pay for.
Every database change matters within seconds.
DebeziumRedpandaClickHouse
Debezium captures each change, Redpanda keeps them in order, and ClickHouse makes them queryable almost as soon as they happen.
Nobody should rely on data that hasn't been checked.
Great ExpectationsOpenLineage
Every batch is validated before it is trusted, and every table can be traced back to the run that produced it.
Infrastructure should be rebuildable from scratch.
AWSTerraform
Cloud resources defined as code, so a client platform is reviewed, versioned and repeatable rather than clicked together.
A change shouldn't merge until it's proven.
GitHub Actions
CI runs the dbt build and tests on every push, so problems surface in a pull request and not in a dashboard.

The stack follows the problem, not the other way around.
